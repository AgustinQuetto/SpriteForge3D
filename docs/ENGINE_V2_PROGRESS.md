# Engine v2 progress

The core v2 scope in `ENGINE_V2.md` is implemented and verified through the authoring-to-export workflow. The evidence below records the checks and their limits.

## Implemented and checked

- Separate engine modules for JSON components, visual asset snapshots, map history, editor integration, runtime, and standalone export.
- Paint/erase/rectangle tools with cell size, named layers, elevation, brush feedback, and undoable strokes. Browser paint → undo → redo → erase returned object counts 167 → 166 → 167 → 166.
- Reusable snapshots of selected objects/groups; independent stamps with new behavior IDs. Resource capture survived a page reload.
- Inspector for enabled state, tags, stable IDs, movement, collider size/offset, named sprite-sheet clips, visual events, and JavaScript hooks.
- Fixed-step movement, solid wall sliding, trigger transitions, nearby interaction, camera follow, pause/stop, and event recursion limits.
- `.s3d` version 4 saves actual visual buffers, textures, editable metadata, nested hierarchy references, and exact affine transforms. Earlier version 3 browser checks preserved 166 demo objects, a resource, and an edited player speed of 120; v4 now preserves edited primitives and multiselection without reconstructing geometry from constructor parameters.
- Playable example: browser traversal around the wall, goal trigger, E interaction, pause/resume, and Stop passed. No browser warnings/errors were reported in these checks.
- Standalone HTML export uses a bundled copy of the same runtime. Exported gameplay reached the goal interaction after fixing and regression-testing matrix serialization.
- Layer creation, selection, rename, visibility, and locking now integrate with map tools, hierarchy selection/delete/drag, and project history. Hidden layers use editor render masks; runtime assets preserve authored visibility. Browser rename/lock/hide/reload retained all 44 wall cells.
- Named clips support per-clip FPS/loop, initial clips, live canvas preview, optional runtime frame-size fitting, directional idle/walk switching, script overrides, animation completion events, and visual animation actions. Browser import of `examples/player-sheet.png`, authoring `idle`/`walk`, capture, and reload retained both clips.
- Direct `.s3d` download/open was checked with a real downloaded file: 167 objects, two templates, layers/flags, clips, and a visual animation action survived. The fallback download now uses Blob URLs.
- Narrow windows have library/inspector toggles and a full-width play view. Browser play showed the animated textured sprite and editor-hidden walls, with no warnings/errors reported.
- The exported textured HTML contains embedded image data and zero external script tags. Direct file launch is unverified because the in-app browser blocks `file://`; no bypass was attempted.
- Visual event authoring supports other-tag filters, AND conditions on numeric variables, one-shot/cooldown rules, ordered action sequences, numeric variables, interpolated messages, and stable object targets with search. Legacy single-action rules migrate without losing behavior.
- Collider authoring includes live selected/all-object overlays, fit-to-visual sizing (including fitted sprite frames), optional height-aware collision, mutual group/mask filtering, and runtime spawn-overlap correction. Generated map walls now initialize collider volumes to their visible geometry.
- Disabling parents suppresses descendant simulation/collisions. First activation initializes scripts once, reactivation preserves runtime state, and stop hooks run for initialized disabled objects. Interaction chooses the nearest active handler; early start signals reach later objects.
- Grouped resource instances and duplicated selections remap internal visual-action targets while retaining external references. Missing targets report contextual diagnostics without stopping subsequent actions.
- Updated demo: collectible key → conditional door → cyan goal. Browser authoring used both presets, collider fitting, a group/height setting, and action reordering. Reload preserved the door's key condition and fitted Y base. Browser gameplay verified no-key refusal, collecting a key, consuming it to open the door, reaching the goal, and the final interaction. Stop restored the authored key and four actions; no browser errors/warnings were reported.
- Object-target search was checked in the browser: searching Door reduced the picker to self/other/Door and selected its stable ID.
- Resources now have rendered PNG thumbnails, name search, rename, update from selection, removal, and undo/redo. Updates retain resource IDs and affect future instances. Browser capture/rename/search/update/removal/undo passed; a downloaded v4 project retained both thumbnails and the updated resource's visual source.
- Project loading validates and prepares detached scenes/resources before committing. Failed preparation preserves the current scene, resource library, and undo history; commit errors roll back the previous scene. Newer loads supersede older loads and partial scenes are disposed. Loading yields in batches for a visible cancellable dialog.
- Browser v4 save/reopen retained 167 objects and two resources while saving a two-object selection. Unsupported version, missing geometry, and undecodable PNG imports were rejected without losing the current scene; undo still reverted a resource rename. Cancelling a 3,000-object load retained the active 167-object animated scene and its resources.
- Browser migration checked a v2 indexed group and a v3 project containing an embedded sprite sheet, two resources, and named idle/walk clips. The latter was saved and reopened as v4. Node checks cover nested scaled/rotated groups, affine shear, zero scale, edited geometry, typed voxel metadata, malformed hierarchy/components, cancellation, stale loads, and staged-resource disposal.
- Hierarchy rendering follows authored parents during temporary multiselection and displays nested groups once. Group deletion removes registered descendants so saves cannot resurrect deleted content. Browser parent-plus-child selection duplicated the group once (1 → 2 objects); undo, delete (1 → 0), and undo restored its child. Node coverage verifies nested groups and restored child order.
- A game exported from the migrated textured v4 project contains embedded images and zero external script tags. On a plain static HTTP server, the textured sprite rendered and gameplay verified solid-wall blocking, navigation around the wall, final interaction, pause, and restart, with no browser warnings/errors. Direct `file://` opening remains unverified due to browser policy.
- Compatible opaque, untextured map meshes use spatial instance batches in the editor and the shared exported runtime. Independent transforms/colors, visibility, camera layers, picking, source snapshots, and undo remain intact. Animation, custom rendering, mirrored/sheared transforms, and changed geometry/materials fall back to ordinary rendering. Helpers stay outside authored roots and are disposed on rebuild/Stop.
- Collision uses a cached spatial index with bounded fallbacks for oversized colliders and swept queries. Exact height/mask/overlap checks and original trigger ordering remain intact. Static entities avoid per-tick movement/animation work. Tests compare indexed simulation to brute-force candidates and analytic affine bounds to all eight transformed corners.
- `npm run benchmark:engine -- --size 64` generates 4,350 objects (4,096 floor cells, 252 walls, player and goal). The recorded CPU run measured 175 ms floor painting, 3.3 ms undo, 300 ms batch creation, and 1.1 ms median / 3.2 ms p95 simulation steps. The benchmark's movement and final interaction passed in editor Play and in the 10.6 MB standalone HTML on a plain static server; its package has zero external script tags.

Browser save → reload recovered all 4,350 objects from the 9.6 MB project without warnings/errors. No temporary render helpers enter the draft.
- Map placements now save local support anchors and reconcile addresses/elevation after object/group transforms, history changes, strokes, and project capture/load. Overlapping placements replace/erase atomically. Browser moved a floor cell to (-2,-2), elevation 8: erase at elevation 0 retained 167 objects, erase at 8 produced 166, and undo restored 167. The downloaded v4 project and autosave reload retained its address and support anchor.
- New empty-state workflow offers a playable example or painting from scratch, with modeling/import options retained. Map → Objects → Play/export guidance avoids model-only instructions. F/Encuadrar frames selections or whole projects in perspective/orthographic views and narrow aspects. Browser checked paint-from-empty, undo, Escape, example creation, and the stacked compact welcome.

## Known limitations and further coverage

- Broader rendering coverage across varied GPUs, dense lights/emitters, imported transparent materials, and narrow effect panels. Shared editor/export lighting, shadows, day/night, particles, post-processing, HTML controls, pause/restart, and persistence now have direct evidence.
- Broaden large-map benchmarks to denser/heterogeneous/textured maps and varied devices; improve batch preparation and large hierarchy/serialization costs where measurements warrant it. Transformed-cell addressing now has direct regression/browser evidence.
- Broader directional-animation and textured standalone-game verification; imported skeletal animation is not supported yet.
- Broader collision stress with dense overlapping triggers and complex overlap/rotated-parent gameplay. Affine collider bounds, spatial candidates, and normal trigger ordering now have oracle/regression checks; axis-aligned collision remains intentional for top-down gameplay.
- Broader event/activation integration checks, complex HTML forms/menu layouts, and custom script behavior in exported games. Templates, syntax validation, line diagnostics, and shared HTML interface controls now have direct evidence.
- Broader browser round trips of imported model formats, edited voxel assets, and unusual material configurations. V2/v3 migration and v4 hierarchy/geometry regression checks are established; not every import format has been exercised end to end.
- Verify direct local-file launch of textured exported games in a browser that permits it. Static HTTP gameplay and embedded-asset packaging now have direct evidence.
- Further responsive/accessibility review of deeper animation/event/object panels. The engine-focused welcome, framing, keyboard HTML controls and compact entry layout are implemented and checked.

The listed follow-ups extend coverage and capabilities beyond the verified core workflow; they are not claims that every device, imported format, or arbitrary user script has been tested.
